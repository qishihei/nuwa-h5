## 上线实测记录（2026-10-27）

在真实线上环境逐项验证，**不是纸上推演**：

| 检查项 | 结果 |
|---|---|
| 两个 GitHub Pages 落地页 | 200，`正在进入…` → 正确跳转各自后端 |
| `nuwa-h5.onrender.com`（思想） | 热实例 1.7s；冷启动曾测得 ~80s |
| `director-salon.onrender.com`（导演） | **冷启动实测 83s**（致命），二次请求 1.9s |
| LLM 真实接入 | ✅ 返回真实框架化回答，**非演示模式** |
| `/api/persons` | 思想家 25 位 / 导演 25 位 |
| 多人对照 | ✅ 正常，`analysis` 整合分析质量好 |
| 保活进程 | 两个服务均已后台运行（10 分钟一轮 ping） |

### 由此发现并已修的两个问题

1. **「同时回答」名不副实（已修）**
   服务端 `slice(0, 5)` + 前端 `size >= 5` **双重硬上限**，一次最多只有 5 位作答 ——
   但封面和投稿文案写的是"25 位大师同时回答你一个问题"。评委一试就穿帮。
   实测 DeepSeek 在 **25 并发下 25/25 全部成功、真实负载墙钟仅 3.4s**，瓶颈根本不是并发。
   已放开到全阵容 25 位：>6 人时自动把单篇收短到 ~220 字（25 篇长文会淹掉手机屏幕），
   整合分析预算相应提到 1400。前端同步加了「全选全部大师 / 选热门 6 位 / 清空」。

   > 本地回归：旧路径 2 人保持 1067 字长回答不变（11.1s）；新路径 25 人平均 219 字（**7.3s**）。

2. **store.json 缺字段会打挂整个对照接口（已修）**
   旧版本写出的 `store.json` 只有 `users`，`recordQuestion` 读 `store.questions` 得到
   `undefined` 直接抛错，`/api/compare` 返回 500。生产环境侥幸没触发，属定时炸弹。
   已加字段自愈（缺哪个补哪个）。

## ⚠️ sharecode 卡点（当前唯一硬阻塞）

表单第 06 项原文：

> 链接必须包含有效的 **sharecode** 参数，提交前请使用浏览器重新打开完整链接，确认其他人可以正常访问和体验；
> 如果链接打不开、需要额外权限或**缺少 sharecode**，可能会影响作品评审。

对照其他参赛者已提交的链接，格式统一为：

```
https://<作品名>.app.workbuddy.host/?sharecode=<10 位大写码>
例：https://warm-isle-milktea.app.workbuddy.host/?sharecode=KBYNIUWL6C
```

即 **sharecode 由 WorkBuddy 发布流程自动生成**，只发不出来的第三方域名（GitHub Pages / Render）拿不到这个参数。

### 现状

| 地址 | 可用 | 带 sharecode |
|---|---|---|
| `qishihei.github.io/nuwa-h5/.../landing` | ✅ | ❌ |
| `nuwa-h5.onrender.com` | ✅ | ❌ |

### 要拿到 sharecode，只有一条路

在 **WorkBuddy 客户端**里把这个作品发出去（本 IDE 没有发布到 `app.workbuddy.host` 的工具）：

1. WorkBuddy 首页切「**开发**」模式 →「开发网站」/「Agent 应用」；
2. 让它生成/发布该作品 → 对话里点「复制应用发布链接」；
3. 拿到的链接形如 `https://xxx.app.workbuddy.host/?sharecode=XXXXXXXXXX`；
4. **用无痕窗口打开验证**能正常用，再填进第 06 项。

> 技术前提：`app.workbuddy.host` 只托管静态站，而我们的问答要靠后端调 LLM（key 不能放前端）。
> 解法已预留 —— `public/config.js` 里 `window.API_BASE` 改成 `https://nuwa-h5.onrender.com`（导演端换成
> `https://director-salon.onrender.com`），静态页就能跨域调后端；`server.js` 已带 `Access-Control-Allow-Origin: *`。
> 但这会重新依赖 Render 保活，冷启动问题回来。

### 决策建议

- **求稳**：先按现有链接提交，把「可能影响评审」当风险接受 —— 两个作品都能真跑，完成度分拿得住；
- **求满**：花半天在 WorkBuddy 里重发布一版静态前端 + 指向 Render 后端，拿到 sharecode 后再提交。
